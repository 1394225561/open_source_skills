# 费曼学习与检测

把一次学习请求变成一个可恢复的学习项目。核心循环是：**规划 → 学习材料 → 闭卷解释 → 检测评分 → 针对性补救 → 再测 → 门禁推进**。

## 触发后的第一步

先识别当前会话是否已经有学习项目：

- 有项目路径：先读取 `00-project.md`、`01-roadmap.md`、`05-progress/progress.md` 和最近一次会话记录，再从 `current_module` 和 `current_state` 恢复。
- 没有项目路径：询问或确认主题、学习目标、起点、可投入时间、期望深度、语言、是否需要练习/项目，以及用户希望的独立项目目录。目录必须是用户明确同意的路径；未指定时，提出一个当前工作区下的候选路径供确认。
- 若用户只想咨询费曼法本身，不创建学习项目，直接回答问题；只有进入实际学习时才执行落盘流程。

确认路径后，运行 `scripts/create_learning_project.py <project_dir> --topic "..."` 创建基础结构；若路径已有项目，禁止覆盖，改为读取并续学。脚本不是学习记录的替代品，所有内容仍由本 Skill 根据对话写入相应文件。

## 交付物与目录契约

项目目录必须独立于 skill 源码目录，并保持以下结构。字段和命名细节见 [project-contract.md](references/project-contract.md)。

```text
<project_dir>/
├── 00-project.md                 # 用户目标、边界、起点、偏好、验收标准
├── 01-roadmap.md                 # 分层路线图、模块顺序、前置关系、完成门槛
├── 02-materials/
│   ├── index.md                  # 资料索引、来源、用途、可信度和阅读顺序
│   └── module-XX.md              # 每个模块的讲义、例子、术语、练习和来源
├── 03-modules/
│   └── module-XX.md              # 模块状态、目标、完成条件、薄弱点
├── 04-assessments/
│   └── module-XX-attempt-YY.md   # 每次检测题目、用户原答、评分、证据和补救
├── 05-progress/
│   ├── progress.md               # 当前状态、模块掌握率、下一动作、更新时间
│   └── changelog.md              # 按时间追加的学习事件
└── 06-sessions/
    └── YYYY-MM-DD-session-XX.md  # 每次学习会话的输入、输出、决定和待办
```

路线图和资料必须按用户的目标、时间和背景定制，不能只给泛泛的书单。外部资料要记录标题、作者/机构、链接或出版信息、访问日期、适用模块和可信度；无法核验的内容标为待核实，不冒充权威。

## 生命周期

### A. 建立路线图

1. 将目标拆成从基础到应用的模块；每个模块只承载一个可检测的能力。
2. 为每个模块写出：学习目标、前置知识、核心概念、最小例子、反例/边界、练习、检测方式和 `mastery_threshold: 80`。
3. 生成 `01-roadmap.md`、`02-materials/index.md`、对应讲义和 `03-modules/module-XX.md`，并在 `progress.md` 标记第一个模块为 `in_progress`。
4. 若主题过大、目标冲突或资料范围会显著影响路线，先向用户说明假设并询问；不要静默决定高影响的学习方向。

### B. 讲授一个模块

先提供该模块的材料和学习任务，让用户自行阅读、练习或完成指定输出。讲授材料遵循费曼原则：先直观模型，再准确术语；明确因果链、前提、边界、常见误区和至少一个新情境应用。对于高风险领域，提醒用户材料仅用于学习，关键结论应由合格专业人士或权威来源核验。

**阶段性学习完成后，必须先提问，不要直接给出答案或长篇复讲。** 提问前只说明检测规则和提交格式，不暗示标准答案。除非用户明确请求即时讲解，否则不得把检测题改成讲义。

### C. 费曼检测

每个模块至少包含以下题型，并混合顺序以避免背模板：

- 闭卷用自己的话解释核心概念；
- 解释机制或因果链；
- 举例或完成一个基础应用；
- 辨析反例、边界或相近概念；
- 一个迁移题：改变条件或换到新情境。

一次检测通常 5 个评分点；复杂主题可拆成更多评分点，但必须在题目前说明总分。接受文字、语音转写、图示描述或代码等能体现理解的输出；不要因表达风格而扣分。

收到回答后，先保存原答，再逐题给出：准确性、完整性、因果/边界、应用迁移的证据。按 [assessment-rubric.md](references/assessment-rubric.md) 计算掌握率，并把评分写入 `04-assessments/` 和 `progress.md`。掌握率 = 得分评分点 / 总评分点 × 100%，不能凭整体印象四舍五入到 80%。

### D. 门禁与补救

- **≥80%**：模块标记 `mastered`，记录证据和残余风险，才允许进入下一模块或用户指定的复习任务。
- **<80%**：模块保持 `remediation`，明确列出未掌握评分点；不要推进下一模块。先提供一种不同表征的补救：生活类比、反例对比、图示/流程、逐步推导、worked example、类比迁移或动手练习，依据卡点选择，不能只把原话换几个同义词。
- 补救必须保持事实正确；若存在多个学派、版本或尚未确定的事实，明确说明争议和采用的范围。
- 补救后只重测未掌握点，并至少加入一道新情境题。连续两轮仍卡住时，降低单次目标、回退到缺失前置模块，或询问用户是否调整深度/节奏；每次决定都记录。
- 只有用户主动要求跳过时才可暂停门禁，并把跳过原因、未掌握点和风险写入记录；不得把跳过报告为已掌握。

### E. 每次交互后的持久化

每次学习交互结束前都要更新：

1. 当前会话文件：目标、用户输出、检测/讲解内容、决定和下一步；字段可参考 [session-template.md](references/session-template.md)；
2. 相关模块文件：状态、已掌握点、薄弱点、下一次检测范围；
3. `05-progress/progress.md`：当前模块、各模块最新掌握率、总体进度和下一动作；
4. `05-progress/changelog.md`：追加一条带时间的事件，包含事实证据，不写空泛的“学习完成”。

写文件失败、路径不可写或用户回答未收到时，明确告知并保留当前对话中的待落盘内容；不得声称已记录。

## 对话行为硬约束

- 阶段性完成后主动提问；等待用户回答，再评分。不要连续讲完全部课程。
- 评分前不泄露答案；评分后指出证据和缺口，避免只给分数。
- 用户卡住时先定位具体评分点，再选择不同解释路径；不得重复同一段表达。
- 任何模块未达到 80% 都不推进；“看起来熟悉”、能复述术语或资料读完不算掌握。
- 区分“知识理解率”和“实践熟练度”。实践技能即使解释达标，也要安排独立练习或项目验收。
- 尊重用户指定的语言、节奏、资料范围和输出形式；调整路线时同步更新 `01-roadmap.md` 和变更日志。

## 完成标准

只有当用户目标对应的模块全部达到至少 80%，并完成约定的综合迁移任务，才报告学习项目完成。最终报告列出每个模块的掌握率、检测证据、仍需复习的风险和已落盘文件；若有跳过、待核实资料或实践能力未验证，必须单独列出。
