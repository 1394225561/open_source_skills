# 小说总编排

把 `chinese-novelist` 作为创作引擎，把本 Skill 作为总编剧、连续性编辑和修订总编。保留其需求问答、人物档案、大纲、逐章写作、润色和进度管理；用可持久化的故事圣经、因果链、状态账本、线索账本和质量门禁补足它。

## 先执行依赖门禁

1. 检查当前会话提供的**可用技能列表**，精确查找 `chinese-novelist`。
2. 不得仅凭文件系统中存在同名目录判断它可用。
3. 若列表中不存在，立即回复：

   > 当前会话的可用技能列表中没有 `chinese-novelist`。`novel-orchestrator` 依赖它执行创作主流程，因此本次不能开始或继续创作。请先确保该 Skill 已加载后重试；我不会自动安装。

4. 回复后停止。不要开始问答、创建项目、安装依赖或模拟 `chinese-novelist`。
5. 若存在，完整读取它的 `SKILL.md`，再按当前阶段读取其直接引用的流程或指南。不得修改其目录。

## 确定工作类型

根据用户材料选择一种入口，不重复询问已有信息：

- **从零创作**：执行完整流程。
- **已有构思或大纲**：抽取已知事实，补齐关键缺口后进入规划门禁。
- **续写项目**：读取现有 `02-写作计划.json` 及本 Skill 的账本，从第一个未完成状态恢复。
- **修稿或审稿**：先建立当前书稿的事实基线，再从对应审校阶段进入；未经授权不要重写正文。

只询问会实质改变作品的决策。用户可以把次要决策交给编排者，但核心卖点、主角欲望、结局承诺和禁区必须明确或被明确标记为待定。

## 总流程

### 1. 锁定创作契约

在调用主流程前明确：一句话故事承诺、目标读者、类型及子类型、篇幅、叙事视角、基调、商业性与文学性侧重、结局性质、内容禁区、必须保留的元素。

把作者或热门作品参考转换成可观察的高层特征，例如叙事距离、句长、信息密度、幽默方式、暴力尺度和情感温度。不得复制独特措辞、具体段落、角色或情节，也不得承诺精确模仿在世作者。

### 2. 调用 `chinese-novelist` 完成立项

使用它的 Phase 0-2 完成偏好加载、必要问答、标题、`00-人物档案.md`、`01-大纲.md` 和 `02-写作计划.json`。不要另造一套重复问卷。

在其规划确认后、开始正文前，复制 `assets/` 中的项目模板并按以下映射生成：

- `story-bible-template.md` -> `03-故事圣经.md`
- `plot-engineering-template.md` -> `04-剧情工程.md`
- `continuity-ledger.template.json` -> `05-连续性账本.json`
- `thread-ledger.template.json` -> `06-线索与承诺账本.json`
- `scene-plan-template.md` -> `07-场景计划.md`
- `quality-report-template.md` -> `08-质量报告.md`
- `revision-plan-template.md` -> `09-修订计划.md`

字段定义和维护规则见 [project-contract.md](references/project-contract.md)。不要把空模板当作已完成产物。

### 3. 执行规划门禁

正文开写前验证：

- 主角的外在目标、内在需要、恐惧、错误信念和不可退让的代价形成冲突。
- 对手有独立目标和可执行策略，不靠临时降智推进剧情。
- 大纲中的关键转折由前一事件和人物选择共同导致，而非“作者需要它发生”。
- 结局先有答案，再反向校验关键铺垫；悬疑、反转和世界规则尤其如此。
- 每个主要人物有关系弧或人物弧；每个主要支线服务主线、主题或人物，否则删减或合并。
- 章节功能有变化，允许人物深化、余波、过渡和氛围章节，不强迫每章使用同一节奏。
- 时间、距离、资源、能力、伤势、身份和角色知识均存在可追踪的初始状态。

发现阻断问题时修订规划并重新检查。通过后在 `08-质量报告.md` 记录证据，不要只写“已通过”。具体标准见 [quality-gates.md](references/quality-gates.md)。

### 4. 逐章编排写作

默认采用串行写作。只有用户明确要求并行、故事圣经已锁定、章节批次之间依赖较弱且账本有唯一写入责任时，才使用 `chinese-novelist` 的并行模式。

每章执行以下闭环：

1. **写前取证**：读取本章大纲、上一章正文、相关人物档案、故事圣经、未解决线索和当前连续性状态。
2. **场景设计**：为每个场景明确视角人物、当下目标、阻力、策略、转折、代价、信息变化和退出状态；写入 `07-场景计划.md`。
3. **交给创作引擎**：使用 `chinese-novelist` 的逐章流程完成初稿、正文润色和字数检查。
4. **事实抽取**：只记录正文中实际发生的状态变化、人物新知识、世界事实、物品流转和时间推进；同步更新两个 JSON 账本。
5. **章节门禁**：检查因果、连续性、人物、视角、承诺、节奏和语言。发现阻断项必须先修正文，再写下一章。
6. **证据留痕**：在 `08-质量报告.md` 记录问题、正文证据、修订动作和结果。

不得用摘要代替上一章正文。不得把计划中但未写入正文的事件登记为既成事实。

### 5. 覆盖底层流程的公式化约束

当 `chinese-novelist` 的通用写法与本书创作契约或章节功能冲突时，按以下规则执行：

- “每章至少 30% 对话”改为由场景需要决定；独处、追踪、氛围和内心转折章可以显著更低。
- “每章至少一个意外转折”改为每章必须产生**有意义的状态变化**；转折只能在有铺垫且有后果时使用。
- “第一段必须即时冲突”改为开篇必须产生阅读牵引；牵引可来自欲望、异常、声音、意象、关系张力或问题，不必总是危机。
- “每章必须章末钩子”改为章末必须形成继续阅读的动力；可用悬念、情感余波、决定、主题回声或阶段性完成。
- “连续 500 字无冲突就加张力”不作为机械计数。允许必要的喘息，但静态段落必须提供信息、关系、氛围或主题价值。
- 字数是范围，不是质量代理；禁止为达标重复信息、堆砌景物或制造无效对话。

这些覆盖只影响当前编排作品，不修改底层 Skill。

### 6. 滚动审计

每完成一个叙事单元或最多 5 章执行一次滚动审计：

- 重算时间线和人物位置，核对旅行、伤势恢复、资源消耗和年龄日期。
- 核对每个角色在每个时间点能知道什么，消除视角泄漏和未获得的信息。
- 核对人物决定是否有动机、触发因素和可见代价。
- 检查未解决线索、读者承诺和关系弧是否被推进；长期静止的线必须处理。
- 检查高潮密度和句法节奏，避免所有章节同强度、同开头、同钩子。
- 运行 `scripts/validate_novel_project.py <项目目录>` 检查账本结构。脚本通过不等于文学审校通过。

### 7. 全稿分轮修订

初稿完成后不要一次性“综合润色”。按 [revision-protocol.md](references/revision-protocol.md) 分轮执行：

1. 故事承诺与整体结构
2. 因果、时间线、世界规则和线索公平性
3. 人物弧、关系弧、动机与知识边界
4. 场景必要性、节奏、悬念和情感兑现
5. 叙事视角、声音、意象、对白和文采
6. 重复、套话、AI 痕迹、标点与格式

结构修改完成前不要精修即将删除的句子。每轮只解决该轮问题，并把跨轮问题登记到 `09-修订计划.md`。

## 问题等级与停止条件

- **阻断**：因果断裂、事实矛盾、时间或空间不可能、角色越权获知、世界规则破坏、关键线索不公平、结局无法由前文推出。修复前停止续写。
- **重大**：动机薄弱、人物弧断裂、场景无变化、承诺长期不推进、节奏持续失衡。当前叙事单元结束前修复。
- **轻微**：重复词、局部句法、标点、非关键措辞。可进入全稿语言轮统一处理。

不得静默跳过问题。若保留矛盾是有意的不可靠叙事、开放结局或续集伏笔，要在账本中写明设计目的和读者可获得的解释边界。

## 完成标准

只有同时满足以下条件才报告完成：

- 正文章节齐全且 `02-写作计划.json` 状态一致。
- 两个账本不存在开放的阻断问题。
- 读者承诺和主要悬念已兑现，或被明确标记为有意开放并获得用户接受。
- 主要人物弧和关系弧在正文中有可引用的起点、转折和落点。
- 结局由前文因果与选择导出，不依赖机械降神。
- 已完成全部修订轮，并在 `08-质量报告.md` 留下具体证据。

最终报告区分：已验证、仍有风险、有意保留。不要把脚本通过、字数达标或模型自评分数称为作品质量已经保证。
