# 自媒体内容工作室

把一次内容生产视为可追溯的判断链：`赛道 -> 人群与场景 -> 可感症状 -> 隐藏原因 -> 真实代价 -> 证据 -> 平台成品 -> 反馈 -> 下一轮假设`。目标不是机械套模板，而是让目标用户在内容里准确识别自己的处境，并获得可信的下一步。

## 入口判断

- 先按本次请求确定范围：完整运营流程使用下述工作区与棋盘；单条创作、平台适配或局部改稿直接进入相关步骤，不为此强制新建工作区或补齐棋盘。已有工作区时保留相关版本与台账留痕。
- 用户尚未说明赛道且无法从稿件或上下文判断时，只先问一个问题：`你想做的赛道或行业是什么？如果已有目标平台，也可以一起告诉我。`
- 用户已说明赛道时，不重复询问。先复述对赛道范围的理解；只有宽窄差异会改变受众或商业模式时，才请用户澄清。
- 完整运营流程中新赛道先建立工作区；已有本 Skill 工作区则读取 `workspace.json`、`赛道档案.md`、`选题台账.csv` 和本次相关选题，涉及选题规划再读 `选题棋盘.md`，从相关状态继续，不重复初始化。
- 工作区默认创建在用户当前工作目录，目录名为 `<赛道>-自媒体`。用户指定目录名或位置时遵从，但不得覆盖已有目录。

## 总流程

### 1. 建立赛道工作区

确定赛道后，运行：

```bash
python3 <skill-dir>/scripts/workspace.py init --niche "<赛道>" --root "<当前工作目录>"
```

脚本只创建结构和空白记录。随后立即完成：

1. 在 `赛道档案.md` 写入已知事实、暂定假设、目标受众、可提供价值、证据资产和禁区。事实与假设必须分开。
2. 读取 [选题棋盘与决策](references/board-and-selection.md)，在 `选题棋盘.md` 填满中心 1 格、内圈 8 格、外圈 16 格，并生成候选选题表。
3. 把初版棋盘展示给用户，指出最关键的 3-5 条候选路径及选择理由。尚未选题且用户未委托代选时，请用户选择或调整后再写正文；已指定选题或授权代选时直接继续。

### 2. 锁定本次选题契约

先复用上下文中的候选方向、目标平台、内容形态、主要目标、目标受众、希望承接的下一步，以及可使用的真实案例或证据。只对缺失且会实质改变成品的核心信息集中询问，不重复确认已明确的选择；非核心项采用合理默认值并标为假设。

创作或跨平台改写前读取 [平台与受众适配](references/platform-and-audience.md)，把本次受众、触达入口、语气、证据呈现和形态选择转成具体写法。局部改稿复用已有判断，仅检查受影响项；不要到制作阶段才替换平台标签。

选择候选时采用 [选题棋盘与决策](references/board-and-selection.md) 的评分维度，但评分只用于比较，不伪装成客观真理。每条入选题必须明确：

- 一个具体人群和一个可拍、可描述的场景；
- 一个用户自己能观察到的症状；
- 一个能改变其理解的隐藏原因；
- 一个真实且不过度恐吓的继续成本；
- 一份现有证据，或明确标注待验证；
- 一个主要内容任务：触达、建立信任、转化或维系，不要求单条内容同时包办全部目标。

使用工作区且本次尚未建档时，按已明确或授权代选的选题运行 `new-topic`，不要手工猜测编号：

```bash
python3 <skill-dir>/scripts/workspace.py new-topic --workspace "<工作区>" --title "<选题标题>" --platform "<平台>" --format "<形态>" --goal "<主要目标>"
```

将选题判断、用户原话、平台与受众适配依据、假设、证据缺口和成功信号写入 `选题简报.md`；无工作区时在交付中简要说明，不额外建档。

### 3. 产出内容

读取 [诊断型内容方法](references/content-method.md)，先形成简短内容论证，再按平台与受众决策写正文；简单改稿只复核受影响的论点，不重复写论证页：

1. 用一句话写清受众看完后应改变的判断。
2. 依次落实场景、症状、隐藏原因、代价和证据；没有证据时降低断言强度，不得虚构案例、数据、客户评价或亲历。
3. 从七种互动动机中选择最多两个服务主题，不为争议而争议，不用虚假翻车、诱导纠错或无法兑现的结果。
4. 让建议形成一个低门槛自测或决策规则，使用户可以完成自我诊断；避免把医疗、法律、财务等高风险判断包装成专业诊断。
5. 根据用户所处阶段设计单一 CTA：继续看、收藏执行、评论反馈、私信咨询或购买，不堆叠动作。

使用工作区时，把正文写入当前版本的 `正文.md`。实质改稿按 [工作区与留痕协议](references/workspace-contract.md) 先创建新版本再修改；发布前不改变含义的排版纠错可在原版本修正并留痕：

```bash
python3 <skill-dir>/scripts/workspace.py new-version --workspace "<工作区>" --topic-id "<选题编号>" --summary "<本轮修改目的>"
```

已经发布的版本永不原地覆盖。

### 4. 制作平台成品

需要制作或交付发布包时，读取 [平台成品规范](references/production-package.md)，按平台、受众和形态交付适用项：标题/封面文案、最终正文或逐镜脚本、画面与素材清单、制作与剪辑指令、发布文案、CTA、必要的话题标签或关键词、可访问性文本，以及发布前检查。纯文本不补音视频制作要求；用户只要正文或局部改稿时不扩成完整包。

- 用户只要求指导时，交付清晰的制作单，不声称已经生成媒体。
- 用户要求实际图片、视频、音频或文档时，使用当前可用且匹配的专用 Skill 或工具，并保留素材来源和授权状态；缺失工具时交付可执行提示词与制作规格，明确哪些仍是计划产物。
- 平台规则、热点、竞品数据或时效性事实会影响成品时，先检索当前资料并把来源、检索日期记录到 `选题简报.md`；无法检索时标记未核验，不凭记忆给出“最新规则”。
- 未经用户明确授权，不登录账号、不发布、不发送私信、不购买投流。

### 5. 质量门禁与确认

交付发布包前逐项检查：

- 前三秒或首屏是否让目标人群识别“这说的是我”，而不是泛泛制造焦虑；
- 隐藏原因是否解释了症状，建议是否由原因自然推出；
- 标题、正文、画面、证据与 CTA 是否承诺一致；
- 每个可核验断言是否有来源，个人经验是否被准确标注；
- 是否泄露客户隐私、使用无授权素材、做绝对化承诺或触碰平台与行业合规边界；
- 平台成品是否完整、可执行，文本是否适配对应媒介而非简单搬运；
- 开头、用词、信息顺序、证据和 CTA 是否回应了本次受众及触达入口，而非套用平台刻板印象；
- 使用工作区时，`选题台账.csv`、`变更记录.md` 和当前版本号是否一致。

按交付范围检查适用项。发现阻断问题就修复并复查受影响项；无法修复时明确告诉用户缺少什么，不把草稿称为最终成品。满足本次要求后停止，不为凑版本或穷尽表达反复改写。

### 6. 发布记录与反馈复盘

进入发布记录或复盘任务时，读取 [工作区与留痕协议](references/workspace-contract.md)。获得实际发布时间、版本和链接/平台记录后，把台账状态更新为 `published`；信息不足时记录用户已确认的部分，不猜测其余字段。按约定窗口把已有的曝光、消费深度、互动、关系沉淀和业务结果写入该选题的 `反馈.csv`，同时记录用户提供或授权访问的高信息量评论和私信原话。

反馈窗口是后续采集计划，不是当前交付的等待条件；没有反馈时交付现有成果，不阻塞等待或自行安排轮询。无工作区的复盘直接报告分析，不强制补建历史档案。

复盘时区分观测与解释：先记录发生了什么，再写为什么可能发生。一次发布只能产生下一轮假设，不能轻率证明因果。使用工作区时把结论写入 `复盘.md`，并回写 `运营实验.md`；涉及场景优先级变化时再更新已有棋盘。

## 完成标准

完成标准随本次范围变化：单条创作、平台适配或局部改稿交付所需结果并通过适用检查即可；以下清单只用于完整运营流程，不得将局部完成称为完整闭环：

- 工作区存在且初版 25 格棋盘、候选路径和赛道档案已落盘；
- 选题由用户指定、确认或授权代选，台账与选题目录编号一致；
- 当前版本包含正文、制作单和发布包，关键断言可追溯；
- 版本修改已留痕，发布状态没有被臆测；
- 若内容已发布且有反馈，记录观测窗口和实际发布版本；反馈未到期或不可得时标为待采集，不声称已完成复盘；若未发布，明确停在 `ready`，不虚构反馈。
