# 自媒体内容工作室

把一次内容生产视为可追溯的判断链：`赛道 -> 人群与场景 -> 可感症状 -> 隐藏原因 -> 真实代价 -> 证据 -> 平台成品 -> 反馈 -> 下一轮假设`。目标不是机械套模板，而是让目标用户在内容里准确识别自己的处境，并获得可信的下一步。

## 入口判断

- 用户尚未说明赛道时，只先问一个问题：`你想做的赛道或行业是什么？如果已有目标平台，也可以一起告诉我。`
- 用户已说明赛道时，不重复询问。先复述对赛道范围的理解；只有宽窄差异会改变受众或商业模式时，才请用户澄清。
- 新赛道先建立工作区；已有本 Skill 工作区则读取 `workspace.json`、`赛道档案.md`、`选题棋盘.md` 和 `选题台账.csv`，从未完成状态继续，不重复初始化。
- 工作区默认创建在用户当前工作目录，目录名为 `<赛道>-自媒体`。用户指定目录名或位置时遵从，但不得覆盖已有目录。

## 总流程

### 1. 建立赛道工作区

确定赛道后，运行：

```bash
python3 <skill-dir>/scripts/workspace.py init --niche "<赛道>" --root "<当前工作目录>"
```

脚本只创建结构和空白记录。随后立即完成：

1. 在 `赛道档案.md` 写入已知事实、暂定假设、目标受众、可提供价值、证据资产和禁区。事实与假设必须分开。
2. 读取 [选题棋盘与决策](references/board-and-selection.md)，在 `选题棋盘.md` 填满中心 1 格、内圈 8 格、外圈 16 格，并生成候选选题表。
3. 把初版棋盘展示给用户，指出最关键的 3-5 条候选路径及选择理由，请用户选择或调整。用户确认前不要进入正文生产。

### 2. 锁定本次选题契约

在一次紧凑交互中确认会实质改变成品的内容：候选方向、目标平台、内容形态、主要目标、目标受众、希望承接的下一步，以及可使用的真实案例或证据。用户不确定的非核心项可以给出推荐默认值，并标为假设。

选择候选时采用 [选题棋盘与决策](references/board-and-selection.md) 的评分维度，但评分只用于比较，不伪装成客观真理。每条入选题必须明确：

- 一个具体人群和一个可拍、可描述的场景；
- 一个用户自己能观察到的症状；
- 一个能改变其理解的隐藏原因；
- 一个真实且不过度恐吓的继续成本；
- 一份现有证据，或明确标注待验证；
- 一个主要内容任务：触达、建立信任、转化或维系，不要求单条内容同时包办全部目标。

确认后运行 `new-topic` 建档，不要手工猜测编号：

```bash
python3 <skill-dir>/scripts/workspace.py new-topic --workspace "<工作区>" --title "<选题标题>" --platform "<平台>" --format "<形态>" --goal "<主要目标>"
```

将选题判断、用户原话、假设、证据缺口和成功信号写入新建的 `选题简报.md`。

### 3. 产出内容

读取 [诊断型内容方法](references/content-method.md)，先写一页内容论证，再写正文：

1. 用一句话写清受众看完后应改变的判断。
2. 依次落实场景、症状、隐藏原因、代价和证据；没有证据时降低断言强度，不得虚构案例、数据、客户评价或亲历。
3. 从七种互动动机中选择最多两个服务主题，不为争议而争议，不用虚假翻车、诱导纠错或无法兑现的结果。
4. 让建议形成一个低门槛自测或决策规则，使用户可以完成自我诊断；避免把医疗、法律、财务等高风险判断包装成专业诊断。
5. 根据用户所处阶段设计单一 CTA：继续看、收藏执行、评论反馈、私信咨询或购买，不堆叠动作。

把正文写入当前版本的 `正文.md`。若用户要求改稿，先创建新版本再修改：

```bash
python3 <skill-dir>/scripts/workspace.py new-version --workspace "<工作区>" --topic-id "<选题编号>" --summary "<本轮修改目的>"
```

已经发布的版本永不原地覆盖。

### 4. 制作平台成品

读取 [平台成品规范](references/production-package.md)，根据形态把内容转换为可直接生产或发布的完整包，至少包含：标题/封面文案、最终正文或逐镜脚本、画面与素材清单、制作与剪辑指令、发布文案、CTA、必要的话题标签或关键词、可访问性文本，以及发布前检查。

- 用户只要求指导时，交付清晰的制作单，不声称已经生成媒体。
- 用户要求实际图片、视频、音频或文档时，使用当前可用且匹配的专用 Skill 或工具，并保留素材来源和授权状态；缺失工具时交付可执行提示词与制作规格，明确哪些仍是计划产物。
- 平台规则、热点、竞品数据或时效性事实会影响成品时，先检索当前资料并把来源、检索日期记录到 `选题简报.md`；无法检索时标记未核验，不凭记忆给出“最新规则”。
- 未经用户明确授权，不登录账号、不发布、不发送私信、不购买投流。

### 5. 质量门禁与确认

交付发布包前逐项检查：

- 前三秒或首屏是否让目标人群识别“这说的是我”，而不是泛泛制造焦虑；
- 隐藏原因是否解释了症状，建议是否由原因自然推出；
- 标题、正文、画面、证据与 CTA 是否承诺一致；
- 每个可核验断言是否有来源，个人经验是否被准确标注；
- 是否泄露客户隐私、使用无授权素材、做绝对化承诺或触碰平台与行业合规边界；
- 平台成品是否完整、可执行，文本是否适配对应媒介而非简单搬运；
- `选题台账.csv`、`变更记录.md` 和当前版本号是否一致。

发现阻断问题就修复并复查；无法修复时明确告诉用户缺少什么，不把草稿称为最终成品。

### 6. 发布记录与反馈复盘

用户提供发布链接或确认已发布后，把台账状态更新为 `published`，记录平台、时间、链接和实际发布版本。读取 [工作区与留痕协议](references/workspace-contract.md)，按约定窗口把曝光、消费深度、互动、关系沉淀和业务结果写入该选题的 `反馈.csv`，同时收集高信息量评论和私信原话。

复盘时区分观测与解释：先记录发生了什么，再写为什么可能发生。一次发布只能产生下一轮假设，不能轻率证明因果。把结论写入 `复盘.md`，并回写 `运营实验.md` 和棋盘中的场景优先级。

## 完成标准

只有以下项目齐全才报告一次内容闭环完成：

- 工作区存在且初版 25 格棋盘、候选路径和赛道档案已落盘；
- 选题经用户确认，台账与选题目录编号一致；
- 当前版本包含正文、制作单和发布包，关键断言可追溯；
- 版本修改已留痕，发布状态没有被臆测；
- 若内容已发布，反馈记录包含观测窗口和实际发布版本；若未发布，明确停在 `ready`，不虚构反馈。
