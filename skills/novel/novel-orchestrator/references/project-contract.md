## 文件边界

在 `chinese-novelist` 创建的单部小说目录中维护以下文件：

| 文件 | 所有者 | 用途 |
|---|---|---|
| `00-人物档案.md` | 底层流程 | 人物初始设计与说话方式 |
| `01-大纲.md` | 底层流程 | 章节级计划与已完成摘要 |
| `02-写作计划.json` | 底层流程 | 章节进度与字数 |
| `03-故事圣经.md` | 编排流程 | 不轻易改变的创作契约、人物弧和世界规则 |
| `04-剧情工程.md` | 编排流程 | 因果链、结构节点、结局反推和支线职责 |
| `05-连续性账本.json` | 编排流程 | 正文已经确立的时间、人物状态、知识和世界事实 |
| `06-线索与承诺账本.json` | 编排流程 | 伏笔、线索、悬念、关系与读者承诺的生命周期 |
| `07-场景计划.md` | 编排流程 | 下一章场景卡及已完成场景的结果摘要 |
| `08-质量报告.md` | 编排流程 | 带正文证据的问题、门禁结果与处理决定 |
| `09-修订计划.md` | 编排流程 | 全稿分轮修订的范围和状态 |

不要向 `02-写作计划.json` 塞入连续性详情；保持底层流程的结构兼容。不要在 `01-大纲.md` 和新账本中重复保存同一批长摘要。

## 建立与恢复

### 新项目

1. 等 `chinese-novelist` 完成 `00`、`01`、`02`。
2. 从 `assets/` 复制模板到小说项目目录并改为上表名称。
3. 用已确认的大纲填充真实内容。
4. 执行规划门禁，全部阻断项关闭后才开始第一章。

### 已有项目

1. 先备份由用户现有流程负责；本 Skill 不私自创建散落备份。
2. 阅读所有已完成章节，不得只依赖大纲摘要。
3. 从正文反向建立状态和线索账本，把无法确定的事实标为 `unknown`，不得猜测。
4. 记录大纲与正文的差异，以正文为已发生事实，以大纲为未来意图。
5. 修复开放阻断项后继续写作。

## 故事圣经

`03-故事圣经.md` 保存慢变化信息：

- 一句话承诺、核心问题、类型承诺、目标读者和结局性质。
- 叙事视角、时态、叙事距离、语言密度、幽默和暴力尺度。
- 主题问题与对立答案，不预写教训。
- 主角、对手和主要配角的目标、恐惧、错误信念、秘密、底线和人物弧。
- 关系弧的起点、压力点、不可逆变化和落点。
- 世界规则、能力边界、代价、资源、制度和禁止临时添加的解决方案。
- 核心意象及其出现阶段，通常不超过三个。
- 明确禁区、必须保留项和用户已接受的开放问题。

故事圣经不是百科全书。只记录会影响选择、因果或表现的设定。正文自然揭示这些设定，不把圣经段落直接粘进小说。

变更已锁定规则时：记录变更原因、受影响章节、需要回修的位置，并由用户确认会改变核心承诺的变更。

## 剧情工程

`04-剧情工程.md` 把“发生什么”变成“为什么必然发生”：

### 因果链

每个关键节点写成：

`前置事实 + 人物选择 -> 直接后果 -> 新压力 -> 下一选择`

若节点只能写成“然后发生”，说明因果或人物能动性不足。偶然可以制造问题，不应连续负责解决问题。

### 结构节点

结构服务作品，不强制使用某一种模板。至少标明：

- 正常状态及裂缝
- 激励事件
- 主角主动进入冲突
- 第一次不可逆代价
- 中段认知或策略变化
- 最低点及其由来
- 最终选择
- 高潮后果
- 新常态

短篇可合并节点；文学性作品可以弱化外部事件，但不能取消人物选择和状态变化。

### 结局反推

先写最终事实和最终选择，再列出它成立所需的：

- 人物能力与心理准备
- 已知信息
- 资源和位置
- 世界规则
- 线索与误导
- 情感关系变化

把这些条件安排到前文，不允许高潮时首次出现关键能力、规则或证据。

## 连续性账本

`05-连续性账本.json` 只登记正文已经确立的事实。顶层结构：

```json
{
  "schema_version": 1,
  "updated_through_chapter": 0,
  "timeline": [],
  "characters": {},
  "world_facts": [],
  "continuity_issues": []
}
```

### timeline

每个事件包含：

- `event_id`：稳定唯一标识，如 `E001`。
- `chapter`、`order`：章节及章内顺序。
- `time`、`duration`：故事内时间；不确定时写 `unknown`。
- `location`、`participants`。
- `cause`：上游事件 ID 或明确原因。
- `effects`：造成的状态变化。

只登记会影响连续性的事件，不把每个动作都写入。

### characters

键使用稳定角色 ID，不使用可能变化的称呼。每个角色跟踪：

- `name`、`aliases`
- `location`
- `physical_state`、`emotional_state`
- `relationships`
- `knowledge`
- `inventory`
- `goals`
- `last_updated_chapter`

`knowledge` 必须注明来源章节。角色只能根据已经亲历、被告知、推断或查证的信息行动。

### world_facts

跟踪已在正文确立的规则、历史事实和限制。每项包含 `fact_id`、`statement`、`introduced_chapter`、`status`。后文改变规则时不能覆盖旧值；新增问题并说明是误解揭示、规则例外还是矛盾。

### continuity_issues

问题等级使用 `blocker`、`major`、`minor`；状态使用 `open`、`resolved`、`accepted`。`accepted` 只用于有意设计，并必须填写读者可获得的解释。

## 线索与承诺账本

`06-线索与承诺账本.json` 的每个 `thread` 包含：

- `thread_id`
- `type`：`plot`、`clue`、`foreshadow`、`relationship`、`theme` 或 `reader-promise`
- `description`
- `planted_chapter`
- `target_payoff_chapter`
- `resolved_chapter`
- `status`：`planned`、`open`、`advanced`、`resolved`、`intentionally-open`
- `evidence`：正文证据列表
- `notes`

线索写清“读者看见什么”，不要只写作者答案。悬疑线索另记谁能接触、可能解释和最终解释，确保读者理论上能够推断。

关系弧和主题承诺也使用 thread，避免只追踪谜题而遗忘情感兑现。

## 场景计划

每个场景卡至少包含：

- 章节、场景编号、时间、地点、视角人物
- 进入状态
- 当下目标
- 阻力与对手策略
- 视角人物采取的策略
- 转折或新信息
- 代价
- 退出状态
- 推进的 thread ID
- 必须保持的连续性事实

场景必须至少改变信息、关系、资源、位置、计划或情绪中的一项。仅承担说明的场景需要改写为人物带着目标获取信息，或删除。

场景计划用于约束，不用于把正文写成提纲扩写。若写作中出现更好的自然发展，先检查其因果和账本影响，再更新计划。

## 质量与修订记录

`08-质量报告.md` 的每条问题写：编号、等级、章节/场景、问题、正文证据、影响、修订动作、复核结果。禁止只记录分数或“感觉良好”。

`09-修订计划.md` 按修订轮管理，记录影响范围和依赖顺序。一个结构修订若影响多个章节，应作为一个变更集处理，避免只修表面症状。

## 更新事务

完成一章后按固定顺序更新：

1. 保存正文。
2. 从正文抽取事实差异。
3. 更新 `05-连续性账本.json`。
4. 更新 `06-线索与承诺账本.json`。
5. 更新 `01-大纲.md` 的章节摘要。
6. 更新 `02-写作计划.json` 的状态和字数。
7. 执行章节门禁并更新 `08-质量报告.md`。

若中途失败，下一次恢复时比较正文文件、`02` 状态和 `updated_through_chapter`。不得静默把不一致一方覆盖掉；先说明差异并重建可验证状态。

## 事实优先级

发生冲突时按以下顺序判断：

1. 用户最新明确决定
2. 已交付或已确认的正文事实
3. 已锁定的故事圣经规则
4. 连续性与线索账本
5. 已确认大纲
6. 场景计划
7. 模型临时推断

低优先级内容不得静默改写高优先级事实。正文中的明显笔误仍应作为问题提出，而不是永久固化。
